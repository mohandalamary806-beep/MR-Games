# تقرير مراجعة وتطوير MR Games v0.5.0

## الإصلاحات المنفذة

- إصلاح زر الرجوع بعد إنشاء حاوية أو تعديلها: كان التطبيق يرجع إلى الصفحة الرئيسية بدل قائمة الحاويات، مع أن شاشة إعداد الحاوية تستدعي `onBackPressed()` بعد الحفظ. أصبح الرجوع يعيد المستخدم إلى قائمة الحاويات، بينما الرجوع من الصفحة الرئيسية يغلق التطبيق.
- جعل تعديل `versionCode` آمناً عند إعادة تشغيل سكربت الدمج؛ لم يعد رقم الإصدار يزيد في كل مرة يُعاد فيها تطبيق التعديلات على نفس مجلد المصدر.
- تحسين توصية الأداء التلقائية عند تعذر قراءة RAM، بحيث تظل مؤشرات عدد الأنوية وميزة Vulkan مؤثرة في التوصية.
- تصحيح عرض معلومات المعالج: اسم SoC يظهر فقط عندما يتيحه Android، بينما `Build.HARDWARE` يظهر بشكل منفصل كمعرّف عتاد ولا يُعرض على أنه اسم SoC.
- استخدام ثابت Android الرسمي لميزة Vulkan بدل كتابة اسم الميزة كنص ثابت.

## إضافات مكتبة الألعاب والتحكم — v0.5.0

- إضافة زر **ADD GAME (.EXE)** في الشاشة الرئيسية ونافذة اختيار ملفات Android عبر Storage Access Framework.
- إنشاء حاوية تشغيل مخصصة باسم `MR Games Runtime` عند الحاجة، دون تغيير الحاويات الشخصية الموجودة.
- إنشاء اختصار Winlator أصلي في مجلد Desktop للحاوية المختارة.
- ربط كل اختصار بملف تحكم مستقل يحوي D-pad وعصوي تحكم وأزرار □ △ ✕ ○ وأزرار الكتف وStart/Select، باستخدام تعيينات Gamepad الأصلية.
- تشغيل اللعبة من زر **PLAY NOW** باستخدام `XServerDisplayActivity` مع `container_id` و`shortcut_path` القياسيين.
- الاحتفاظ بملف EXE الأصلي عندما يكون ضمن محركات D: أو E: المشتركة. إذا لم يكن كذلك، تُنسخ نسخة EXE فقط إلى مساحة MR Games الداخلية ويظهر تنبيه بأن ملفات اللعبة المجاورة قد تحتاج نسخاً يدوياً.

## الاختبارات التي أُجريت

- فحص صياغة سكربت Python بنجاح.
- اختبار تحديث رقم الإصدار مرتين على نفس الملف؛ بقي `versionCode` ثابتاً بعد التطبيق الأول.
- التحقق من أن صورة الأيقونة PNG مربعة وقابلة للقراءة.
- مراجعة نقاط الدمج الأساسية مع ملفات Winlator الحالية: شاشة النشاط الرئيسية، قائمة التنقل، إعداد الحاوية، إعدادات Box64، وموارد التطبيق.
- مراجعة واجهات Winlator الأصلية لإنشاء الحاويات، وإنشاء واكتشاف اختصارات `.desktop`، وملفات `.icp`، وقراءة `controlsProfile` عند تشغيل اللعبة.
- تحقق ثابت من صياغة Java وJSON وملف ZIP. لم يتم تنفيذ تثبيت وتشغيل على جهاز Android حقيقي من هذه البيئة.

## حدود الاختبار

الحزمة تحتوي على سكربتات الدمج والملفات المخصصة، وليست مستودع Winlator الكامل. لم يتم إنتاج APK محلياً؛ بناء APK النهائي يحتاج مصدر Winlator الكامل وبيئة Android SDK/NDK، ويُنفّذ ذلك في GitHub Actions حسب ملف Workflow المرفق. لذلك يلزم اعتبار نجاح البناء على GitHub واختبار APK على جهاز Android خطوة تحقق نهائية منفصلة.
